## Supported local maintenance

The site is bilingual: Australian English at existing URLs and Simplified Chinese at matching `/zh/` URLs. The main navigation places 中文服务 after Contact, and each Chinese page returns to its matching English page. Maintain source copy and `data/i18n/zh-Hans.json` together; reviewed wording and terminology belong in `zh-Hans-overrides.json`. Run `node scripts/apply-seo-maintenance.mjs` to regenerate both languages and `node scripts/bilingual-site.mjs --check` to reject missing translations or stale outputs. This check is offline and does not silently fall back to English. Public-source initial translations may be refreshed explicitly with `--translate`; review them before accepting. Never submit customer data to translation services. Run `node --test tests/bilingual-site.test.mjs` for parity, links, freshness and localised confirmation checks. This feature was requested as a local candidate; publication still requires user approval.

Run `node scripts/apply-seo-maintenance.mjs` (or `--root <checkout>`) for supported repeatable maintenance. Authored HTML remains the page source; `data/service-repair-copy.mjs` and `scripts/service-repair-content.mjs` own the eight service-specific editorial replacements, `about-company.mjs` owns the company main region, `deep-guides.mjs` and its content data own the six guide articles, and `project-evidence-navigation.mjs` owns shared Projects navigation and evidence links. Heading/presentation transforms keep titles and collection semantics coherent. Eight keyword sections are protected by committed `data/keyword-content-sections.json`, allowing only the explicit editorial transform: missing sections are restored and unexplained changes or duplication fail for review. Responsive images, schema relationships and discovery resources are maintained without rebuilding authored service pages. The final `enquiry-flow.mjs` hook owns the Task 1 CTA destinations and accessible form contract.

The fixed sitemap significant-change manifest records the six guides’ major 2026-10-14 update and the services, company/project hub, collection and nine indexable locality content edits on 2026-10-15. Shared navigation or contextual evidence links alone do not reset an article’s major-update date. Guide visible dates, Article `dateModified` and structured feeds retain the same major-update baseline; no publication date is inferred. Unaffected page dates remain stable and reruns never assign today’s date.

The supported locality workflow is `node scripts/build-local-waterproofing-pages.mjs --verify`. It regenerates its 24 owned locality pages and synchronously calls maintenance after writing pages and discovery resources. `--check` remains read-only. Run `node --test tests/*.test.mjs` for repository checks; this suite exercises the locality generator, so run maintenance after any interrupted generation. Maintenance never calls the generator or external endpoints.

Other historical scripts rewrite authored service/guide text and metadata and are not a safe full-site regeneration workflow. Do not batch-run them against this checkout. Evaluate future template changes in an isolated copy, preserve authored content, then run maintenance and verify the diff before accepting it. Source assets and responsive manifest must be present; image derivatives are generated separately by the Task 1 image workflow.

See [audit status and evidence checklist](docs/seo/2026-10-10-remaining-audit-status.md) for production/account/evidence work still outstanding. AI crawlers retain the default public access in robots.txt; llms.txt is a canonical content index and does not replace robots or guarantee search/AI visibility. No remote publication or submission is part of maintenance.
